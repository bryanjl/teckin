# Decisions

Newest last. Each entry: date, decision, options considered, reason.

- **2026-10-08 — Build runs autonomously, local only.** Decided by Bryan. Claude makes all build decisions, commits to `main`, and writes deploy scripts without running them.
- **2026-10-08 — Theme: Cogspire.** Chosen from the three concepts in the spec because the energy mechanic is visible on the character.
- **2026-10-08 — Ranking at time-out: current height; zero energy: slow free crawl.** Spec defaults, adopted so the build does not wait on them.
- **2026-10-07 — Working names: platform "Teckin", game "Cogspire".** Options: invent a new platform name, or use the repository name. The repository name is neutral and already in use; package scope is `@teckin/*`. Easy to rename later.
- **2026-10-07 — Toolchain versions.** Node 22, pnpm 10.28, Turborepo 2.11, Next.js 16.4 (Turbopack), React 19.3, Tailwind 4.3, Zod 4, Vitest 5, Playwright 1.63, ESLint 10. TypeScript pinned to 6.0 rather than 7.0 because typescript-eslint supports only `<6.1`; revisit when it supports 7.
- **2026-10-07 — ESLint without `eslint-config-next`.** Flat config built from `typescript-eslint`, `@next/eslint-plugin-next` and `eslint-plugin-react-hooks` in `packages/config`. Avoids `eslint-plugin-react`, which lags new ESLint majors; `next lint` no longer exists in Next 16 anyway.
- **2026-10-07 — Workspace packages ship TypeScript source, no build step.** Options: compile each package with tsup, or consume source. Source keeps the loop fast; Next.js uses `transpilePackages`, Vitest and `tsx` run TS directly. The realtime server gets a bundling step when it is containerised (Phase 3).
- **2026-10-07 — "Shared packages never import a game" enforced by lint.** `sharedPackageConfig` in `packages/config` adds a `no-restricted-imports` rule for `@teckin/climber` to every shared package.
- **2026-10-07 — `game-contracts` stays DOM-free.** The client mount target is typed structurally (`ClientGameMountTarget`) so the server can import the contract without DOM types.
- **2026-10-07 — Climber package layout.** Code in `games/climber/src/{client,server}`, theme packs in `games/climber/themes/`, matching the spec's intent while giving one `src` root for tsconfig and lint.
- **2026-10-07 — Playwright uses Chromium for all four device profiles** (iPhone SE and Pixel 7, portrait and landscape). The iPhone profiles emulate viewport, DPR and touch, not WebKit; real Safari is covered by Bryan's manual phone check. `PLAYWRIGHT_CHROMIUM_EXECUTABLE` lets a preinstalled Chromium be used instead of downloading. E2E runs against `next start` (production build) for stable timings.
- **2026-10-07 — Turborepo agent guidance disabled** (`agentGuidance: false`) so `turbo` does not write an `AGENTS.md` into the repo on each run.
- **2026-10-07 — Fonts: system font stack only.** No web fonts yet, so no font licences to record.
- **2026-10-07 — Phaser 4.2.1.** Latest stable on npm (published July 2026); v4 keeps the v3 APIs used here (`Game` config, `Scale`, Arcade `existing`/`collider`, scene `pause`/`resume`), checked against the shipped type definitions. Imported as `import * as Phaser from 'phaser'` (the ESM build has named exports). Lazily loaded chunk is about 360 KB gzipped, inside the 3 MB first-load budget.
- **2026-10-07 — Input and controls live in the DOM, not in Phaser.** Options: Phaser's keyboard/pointer input with canvas-drawn buttons, or DOM listeners and HTML buttons over the canvas. DOM wins: `env(safe-area-inset-*)` works directly in CSS, buttons are real accessible elements, every finger is tracked by `pointerId` with pointer capture, and the input code is unit-testable without a canvas. Phaser's keyboard plugin is disabled.
- **2026-10-07 — `engine-core` has two entry points.** `@teckin/engine-core` is Phaser-free (input, page guards, pause, wake lock, scaling maths) and safe anywhere; `@teckin/engine-core/phaser` holds boot helpers and is imported only from lazily loaded client code. `@teckin/climber/client` is the game's lazy client entry, imported by `/play/solo` inside `useEffect`.
- **2026-10-07 — Sharp rendering on high-density screens.** Canvas sized in device pixels with `Scale.NONE` and zoom `1/resolution`, resized by a `ResizeObserver` on the mount element. Resolution is capped at 2 to protect fill rate on the baseline Android; revisit with real fps numbers from Bryan's phone check.
- **2026-10-07 — Landscape keeps 11 tiles of height visible.** The world (12 tiles wide) fills the width in portrait; in landscape the zoom is capped so at least 11 tiles of climb stay visible, leaving side margins rather than a thin strip.
- **2026-10-07 — Pause model.** `PauseController` with reasons (`hidden`, `player`); the game runs only when none hold, so a player-paused game stays paused after switching apps. Pausing pauses every running scene (no update or physics step) and releases all held inputs. Covered by an E2E test that hides the tab mid-jump.
- **2026-10-07 — M1.2 uses a sandbox scene.** Rectangles and a short staircase prove boot, scaling, input, pause and camera on a phone. M1.4 replaces it with the platformer-kit controller (coyote time, buffering, variable jump) and Tiled maps. Physics numbers already live in `ClimberTunables.physics`.
- **2026-10-07 — Test hooks behind `?debug=1`.** `window.__teckinGame` (player snapshot, held actions, status, fps) exists only with the debug flag; the mount element always carries `data-game-status`. Multi-touch is tested with CDP `Input.dispatchTouchEvent` (two simultaneous touch points) and safe areas with CDP `Emulation.setSafeAreaInsetsOverride`, both Chromium-only, which matches the Playwright setup.
- **2026-10-08 — SVG rasteriser: `@resvg/resvg-js` 2.6.2 (MPL-2.0), PNG encoding with `pngjs` 7 (MIT).** Options: `sharp` (Apache-2.0, libvips, heavier native install), headless Chromium (slow, fragile in CI), resvg. resvg renders SVG accurately with prebuilt binaries and no system libraries; system fonts are not loaded because art carries no text, so output is identical on every machine. Both licences are open and permit use; resvg is only a build-time dependency and never ships to players.
- **2026-10-08 — Theme pack format.** A folder with `theme.json` (names, colour tokens, font stack, sprite colour variants), `sprites/*.svg` (atlas art, sized in world pixels) and `ui/*.svg` (DOM icons drawn with `currentColor`, inlined into the manifest so buttons stay sharp at any density). The build writes `atlas@{1,2,3}x.png/.json` (Phaser JSON-hash) and `theme.manifest.json`. Player colour variants are find-and-replace colour swaps of one SVG declared in `theme.json`, so 8 variants cost one drawing.
- **2026-10-08 — Art build lives in `@teckin/engine-core/art` (Node-only entry); each game runs it from its own `build` script.** Atlases are generated, not committed: `games/climber/dist/themes/` is a Turborepo `build` output, and the web app's `prebuild`/`predev` copy it to `public/game-assets/climber/` (gitignored). `turbo dev` now depends on `^build` so `pnpm dev` builds art first. Packing is a deterministic shelf packer with power-of-two widths and 2 px edge-extruded padding (no seams between tiles under linear filtering).
- **2026-10-08 — The app tells the game where its assets are.** `ClientGameMountOptions` gained `assetBaseUrl` and optional `themeId`; the play page passes `/game-assets/climber/` and `NEXT_PUBLIC_CLIMBER_THEME`. `?theme=<id>` (kebab-case only) overrides for previews. A missing or incomplete theme falls back to the default rather than failing, and each game declares `ThemeRequirements` that a unit test checks against every theme folder.
- **2026-10-08 — Physics stays on invisible rectangles; art follows.** Sprites are drawn from the atlas at world size (`scale = 1 / textureScale`) and the player image is synced to its body on `POST_UPDATE`. Swapping art can never change collision. The atlas resolution is chosen once at scene preload from render resolution × camera zoom; it is not reloaded on rotation.
- **2026-10-08 — Movement runs on the platformer kit's own pure simulation, not Arcade physics.** Options: Arcade bodies with the jump rules layered on top (the spec's stack table), or a small fixed-step tile simulation in `platformer-kit`. Chose the pure simulation: it is deterministic at any frame rate (fixed 1/120 s step with interpolated drawing), unit-testable without a canvas (the bundled course is proven climbable by a bot in Vitest in milliseconds), and the realtime server can run the same code to validate movement in Phase 3. Phaser now only draws; `bootPhaserGame` makes Arcade optional (`gravityY` omitted means no physics plugin). Moving platforms (M2.5) will need carrying riders in the kit.
- **2026-10-08 — Floating platforms are one-way ledges; the ground is solid.** Tiles carry a `collision` property (`solid`, `oneWay`, `empty`) and a `frame` property in the Tiled tileset. One-way ledges let players jump up through them from below, which is far kinder on touch controls for a vertical climb, and falling still lands on any ledge below. Solid tiles remain available for walls and hard sections in later summits.
- **2026-10-08 — The course map is generated from a compact layout, but stays a real Tiled map.** `games/climber/src/course/course-layout.ts` lists platforms per summit; `pnpm --filter @teckin/climber generate:course` writes `maps/course.json` (Tiled 1.11 JSON with a collection-of-images tileset pointing at the placeholder SVGs, so it opens in Tiled). A test fails if the file drifts from the layout. If a map is ever hand-edited in Tiled, drop it from the generator. The map JSON is excluded from Prettier so Tiled and the generator own its formatting.
- **2026-10-08 — Course height: six summits of 1,000/6 m each, mapped piecewise.** The HUD height is linear between the start (0 m) and each summit ledge (n × 166.7 m), so summit 2 always reads 333 m whatever the map's tile spacing. Summits count only when the player stands in the summit zone (jumping up through it does not count) and only in order.
- **2026-10-08 — Checkpoints: each summit is a checkpoint when `?checkpoints=1`.** After falling more than 3 tiles below the saved checkpoint a "Back to checkpoint" button appears under the HUD; respawning is a choice, not automatic, so a player can still recover by climbing.
- **2026-10-08 — An in-page autopilot proves the course end to end.** `?debug=1&autopilot=1` lets `CourseBot` press the same actions through the same `ActionState` a player uses. The E2E test climbs to the course-complete screen in all four device profiles (about 40 s each). The bot reads only the collision grid and the player state, so it doubles as the Phase 2 scripted playtester.
- **2026-10-08 — Course time counts simulated time.** The clock advances only with simulation steps, so paused or hidden time never counts and the time shown matches the climb exactly.
- **2026-10-08 — Web hosting layout: Front Door in front of both App Service and Blob Storage on one host name.** Options: assets on a separate CDN host (needs CORS and an asset-URL setting in the app), or one Front Door endpoint routing `/game-assets/*` to blob and everything else to App Service. One host keeps the game's asset URLs unchanged and avoids CORS. App Service accepts only this profile's Front Door traffic (service tag + `X-Azure-FDID`); its SCM site stays open for zip deploys.
- **2026-10-08 — Next.js standalone output only for deploys.** `NEXT_OUTPUT=standalone` switches it on (with `outputFileTracingRoot` at the repo root), so local runs and E2E keep `next start`. The deploy installs with `--config.node-linker=hoisted`, because pnpm's symlinked layout broke the traced server once copied (`@swc/helpers` not found); hoisted gives a 62 MB package that ran locally. `NEXT_OUTPUT` and `NEXT_PUBLIC_*` are Turborepo build inputs so cached builds never mix the two outputs.
- **2026-10-08 — Storage without shared keys.** Asset uploads use Entra auth (`--auth-mode login`); the template grants the deploy principal Storage Blob Data Contributor when its object id is passed. The deploy workflow uses OIDC federation with repository variables only, so there are no secrets to store.
- **2026-10-08 — Deploy workflow guards.** Manual `workflow_dispatch` only, `main` only, `pnpm check` before anything ships, GitHub environments per target so Bryan can add required reviewers for prod. CI validates the Bicep offline (`az bicep build`, no sign-in).
- **2026-10-08 — The Climber theme is a build-time setting.** `NEXT_PUBLIC_CLIMBER_THEME` is baked in by Next.js, so the deploy sets it from the `CLIMBER_THEME` variable at build time rather than as an App Service setting.
- **2026-10-08 — Debug-only test hooks `setAutopilot` and `dropToStart`.** They let an E2E test reach summit 1 with the bot, then simulate a long fall to check "Back to checkpoint", without a hand-written fall route. Like the other hooks, they exist only with `?debug=1`.
- **2026-10-08 — Theme-swap acceptance test serves a generated theme through Playwright routing.** The test builds a recoloured, renamed copy of the placeholder folder with the real build and serves it at the normal theme URL, then checks HUD names and that most screen pixels take the new sprite colour. Nothing extra ships in the app.
- **2026-10-08 — Double-tap-zoom guard never cancels a touch that ends on a button.** Cancelling `touchend` also cancels its click, which swallowed quick taps on Pause or Play again. Buttons use `touch-action` to opt out of double-tap zoom instead.
- **2026-10-08 — Phase 2 built in one session at Bryan's request.** He asked directly for "the next phase", which overrides the one-milestone-per-run rule for this run only; each milestone is still committed green on its own.
- **2026-10-08 — Questions package shape.** Zod schemas validate sets (shared later by CSV import and the server). Players only ever receive a `PresentedQuestion` without answers. `QuestionDeck` takes a seedable random source so bot playtests repeat exactly. A wrong answer returns after 3 other questions; in sets too small to wait, it returns as soon as nothing else is left. Multiple-choice options are reshuffled each time a question is shown; true/false keeps True before False. Option ids are short letters (`a`–`d`, `true`/`false`) in seed JSON; the database will use its own ids.
- **2026-10-08 — The platform hands games a `ClientGameShell`.** It carries the `GameSession`, the shared question sheet and results screen, and sound. The web app implements it with React components from `@teckin/ui`; the Phaser game stays framework-free and asks the shell to open the sheet. Options: the game rendering React itself, or vanilla DOM components in `ui`. The shell keeps one React tree owned by the app and lets Phase 3 swap `LocalSession` for `NetworkSession` without touching the game.
- **2026-10-08 — `GameSession` lives in `game-contracts`; implementations in a new `@teckin/session` package.** Interface types are shared by every game and the server; `LocalSession` (and later `NetworkSession`) are client implementations, so they get their own package instead of bloating `game-contracts` or `engine-core`.
- **2026-10-08 — Energy rules.** A jump needs its full cost (10 energy with 5 left does not jump); walking costs 1 per whole tile moved sideways (air included); only an empty meter switches to the free crawl at 35% speed. The session owns the balance and never lets it go negative; the run asks it to spend. `ClimberRun` holds all of this without Phaser, so the scene, tests and the playtest bot share it.
- **2026-10-08 — The energy meter is the "Get energy" button.** One 96 × 56 px control at top left, beside the centred HUD and the pause and mute buttons at top right. The bottom of a portrait phone is taken by the movement controls, and a single target is easier to learn.
- **2026-10-08 — While the sheet is open the run is frozen, not paused.** The scene stops stepping (no movement, no falling, no clock) and drops any held input; the status reads `answering`. The pause controller stays for tab-hidden and the pause button.
- **2026-10-08 — Debug oracle for the autopilot.** With `?debug=1` the solo shell exposes `debugCorrectOptionFor`, so the autopilot and E2E tests answer through the real sheet. It never exists in networked play, where answers stay on the server.
- **2026-10-08 — Sound is synthesised with Web Audio** (oscillator recipes, no files, nothing to license); the mute choice is stored in `localStorage` under `teckin.muted` when allowed. Jumps also give an 8 ms vibration where supported.
- **2026-10-08 — Cogspire art.** All original SVG, drawn for this project. Optional theme frames (`background-<n>` per summit, `energy-key`, `energy-glow`) add polish without being required, so the placeholder theme still works; hazard frames are required and both themes supply them. Energy is shown on the robot itself: the key turns faster and the glow brightens with energy. The energy word stays "Energy" for young readers.
- **2026-10-08 — Atlas edge capped at 2048 px** (was 4096). The 3x Cogspire atlas came out 256 × 2332; some older Android GPUs only guarantee 2048. The packer now picks a squarer layout.
- **2026-10-08 — Mute sits under the pause button.** Beside it, the centred HUD overlapped it on a 375 px screen.
- **2026-10-08 — Hazards are a pure `HazardField` in `platformer-kit`, clocked by course time.** Every moving platform position and every vent or barrier switch is a function of the course clock, so the Phase 3 server can check positions against the same timeline. Crumbling ledges depend on where a player stood, so each run works on its own copy of the collision grid (`CollisionGrid.clone`). Hazards sit around the controller step (carry and push before, platform landing and barrier hits after) instead of inside it, so the controller stays simple.
- **2026-10-08 — Moving ledges only move sideways and sit on tile rows.** Enough for the "ride it across" challenge, and it keeps landing, carrying and the bot's ledge maths simple. Riding and vent pushes are reported as `pushedX` and never cost walking energy.
- **2026-10-08 — Barrier hit = knocked down.** A live barrier sets a downward speed of 350 px/s and uses up the double jump, so the player drops to a lower ledge; it never costs energy. Beams flicker for 0.6 s before switching on so players can time them.
- **2026-10-08 — Hazards placed so the bot proves the course.** Each mover swings under a ledge that is too high to reach without it; crumbling ledges are 3 tiles wide with a 0.9 s delay; the bot waits while a barrier on its path is on or due within 1.1 s. The bot climbing all six summits is a unit test.
- **2026-10-08 — E2E keeps the long run to one profile.** All four profiles climb past summit 2 (the Phase 1 criterion); iPhone portrait plays the whole course to the results screen (about 3.5 minutes in the sandbox), which keeps CI time reasonable.
- **2026-10-08 — Movement costs after the playtests: jump 24, double jump 30, walking 2 per tile** (spec starting values 10/15/1). With the spec values, the scripted skilled player finished in about 6 minutes after only about 20 questions. Energy per correct answer, the host's setting, stays at 100. The "Get energy" pulse stays below 20 as the spec says. Numbers and profiles are in `docs/playtests.md`, and a unit test keeps the skilled time between 8 and 12 minutes.
- **2026-10-08 — Playtest profiles model people, not the bot.** Each profile adds a pause after landing, a chance of fumbling a jump (short hop, no double jump), slower answers and lower accuracy on top of the perfect bot. A person in a steam blast or on a shaking ledge does not pause. Players top up while standing on a ledge.
- **2026-10-08 — The game clock keeps running while the sheet is open; the player and their hazards do not.** Per the spec, a wrong answer "costs time, not energy", so answering counts toward the finish time. Moving ledges and barriers stay frozen with the player so the climb resumes exactly. Phase 3 has to validate movement against each player's own hazard clock.
- **2026-10-08 — Walking energy is charged only for steps on a ledge.** "Falling never costs energy", so drifting sideways in the air is free. Jumps already pay for their own flight.
- **2026-10-08 — Keys inside dialogs and form controls belong to them.** The game's keyboard source ignores events from `[role="dialog"]`, inputs and selects, so Space presses a focused answer button and arrows move the tuning sliders.
- **2026-10-08 — `GameSoundPlayer.unlock()`.** The play page unlocks audio on the first tap or key press, because iPhones only start audio in response to a gesture and the first game sound (a jump) happens in the frame loop.
- **2026-10-08 — Colyseus 0.18 (`@colyseus/core` 0.18.18, `@colyseus/schema` 5, `@colyseus/sdk` 0.18), all MIT.** The docs site could not be fetched from the build environment, so the API was checked against the installed packages' type definitions and source (`defineServer`, `defineRoom`, `createRouter`/`createEndpoint`, `onDrop`/`onReconnect` with `allowReconnection`, `schema()`/`t` state, `room.request`). Only the needed sub-packages are installed, not the `colyseus` meta-package (which pulls in auth, monitor and playground).
- **2026-10-08 — Room logic is a framework-free `LiveGame` plus a thin Colyseus `BaseGameRoom`.** Lifecycle, roster, caps, locks, kicks, renames and the timer live in plain TypeScript with an injected clock, so they are unit-tested without sockets and survive Colyseus API changes. `BaseGameRoom` maps them onto Colyseus state and messages; games extend it through protected hooks (`onPlayerAdmitted`, `onLifecycleEvent`, `onTick`, …) and `RoomStateBase.extend`.
- **2026-10-08 — The room protocol lives in `game-contracts`.** Join options, host commands and close codes are Zod schemas shared by server and browser, so the web app never imports server code.
- **2026-10-08 — Join codes live in Colyseus presence** (`teckin:join-code:<code>` → room id, 30-minute TTL refreshed while the game runs, freed when the game ends). Presence is Redis when `REDIS_URL` is set, so every process sees every code, and in-memory otherwise. Presence has no set-if-absent, so a claim checks the code is free, writes it and reads it back. Codes never start with 0 so they cannot look shorter.
- **2026-10-08 — A browser device key doubles as the reconnect token.** Players send a random key their browser keeps (no personal data); the room stores only its SHA-256. A returning key resumes the same player even after the Colyseus seat (kept 180 s for automatic reconnects) has expired or the tab was killed; it also makes a kick stick until the host allows kicked devices back. Options: Colyseus reconnection tokens only (lost when iOS discards the tab) or a separate token (one more secret to keep). Returning players skip lock, cap and late-join checks because they are already in the game.
- **2026-10-08 — Players have a stable `playerId` separate from the connection's `sessionId`.** The first session id becomes the player id; a player asks `room:whoAmI` (a Colyseus request) to learn it, because messages sent during `onJoin` arrive before the client can listen.
- **2026-10-08 — Host screens join the room with a host key.** `/dev/games` (Phase 3 only, behind `DEV_GAME_SECRET`) makes a random host key, gives it to the creator and passes only its hash to the room. Several host screens may join (laptop and projector); host commands from anyone else are dropped and logged.
- **2026-10-08 — Rooms do not auto-dispose.** A game survives everyone briefly disconnecting (a projector refresh); it closes 10 minutes after ending, or after 30 minutes with nobody connected.
- **2026-10-08 — Join-code lookups are rate-limited per address in each process** (30 a minute, fixed window). Per-code limiting and a shared Redis limiter are left for Phase 4's "join codes and sign-in are rate-limited" criterion.
- **2026-10-08 — Tests boot Colyseus on a free port.** `@colyseus/testing`'s `boot` always uses port 2568, which collides when Turborepo runs packages in parallel; `@teckin/room-core/testing` wraps the same test helpers on a free port. CI starts a Redis service so the cross-process join-code test runs; locally it runs when `REDIS_URL` is set.
- **2026-10-08 — `docker-compose.yml` binds Redis and Postgres to localhost only** with a throwaway local password for Postgres, documented as such; no secrets.
